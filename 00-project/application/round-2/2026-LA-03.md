# Player Feedback Data Warehouse

## My interpretation of the brief

My understanding of this project is that the main objective is to design and implement a data warehouse that integrates player feedback from multiple internet sources into a unified model suitable for analysis.

The project focuses on three specific games: Counter-Strike 2, Cyberpunk 2077, and Grand Theft Auto V. Feedback must be collected from at least two different sources, including Steam reviews and YouTube comments. Since these sources provide differently structured data, an important part of the project is designing a staging layer and an ETL or ELT process that can clean, standardize, transform, and integrate the source data.

The original source and loading time must remain traceable in the staging layer. The resulting dimensional warehouse should support analysis by game, source, time, language, and feedback type. The system must also handle practical data-quality problems such as missing values, duplicate records, different timestamp formats, and source-specific structures.

The project requires processing several hundred thousand reviews or comments and supporting incremental data loading. At least ten complex analytical queries must be developed, followed by performance analysis and optimization of at least five selected queries.

## Proposed approach

I would begin by investigating the official or documented access methods for Steam reviews and YouTube comments and identifying the data available from each source. I would design the collection component so that source-specific data can be stored without losing the original information required for traceability.

The staging layer would store raw or minimally processed records together with information such as the source and loading time. I would then develop an ETL or ELT process to clean and standardize the data before loading it into the dimensional warehouse.

I would compare at least two possible dimensional modeling approaches. One important design decision would be whether feedback from different sources should be represented in one common fact table or separate fact tables. I would compare these approaches in terms of query simplicity, maintainability, integration requirements, and analytical flexibility before selecting and documenting the final design.

The warehouse would include dimensions for at least game, source, time, language, and feedback type, together with a central fact structure representing individual feedback records. The ETL process would handle differences in timestamp formats, missing values, duplicate records, and source-specific attributes.

I would implement incremental loading so that newly collected feedback can be added without unnecessarily reprocessing the entire dataset. Appropriate keys and duplicate-detection mechanisms would be used to maintain data quality.

After building the warehouse, I would create at least ten complex analytical SQL queries covering temporal trends, comparisons between the three games, source-based analysis, language distribution, and positive and negative feedback proportions. I would select at least five queries for performance analysis and investigate indexing and query optimization based on measured results.
