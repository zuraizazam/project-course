# Language Learning Assistant with Individual Progress Tracking

## My interpretation of the brief

My understanding of this project is that the main goal is to develop a database-centered language learning system that tracks individual learning history and determines which learning items should be practiced next based on previous performance.

The system must support one selected foreign language, either English or German, and manage learning items such as words or expressions, meanings, example sentences, topics, and difficulty levels. It must also record practice sessions, exercises, user answers, and learning results.

The central challenge of the project is the recommendation or selection logic for the next practice session. This logic must be implemented on the database side using stored procedures or functions rather than being calculated independently by the user interface. The selection process must consider factors including correct and incorrect answers, the time of the last practice, the number of repetitions, and the difficulty of the learning item.

I understand that the project also requires the implementation and comparison of at least two different selection strategies. For example, one approach could use a simple rule-based system, while another could calculate a weighted priority score. The system must be tested with a significant amount of generated learning-history data, and the performance of the recommendation process and analytical queries must be investigated.

The web or mobile interface should remain relatively simple and act mainly as a way for users to start practice sessions, submit answers, and view their learning progress.

## Proposed approach

I would first define the learning domain and select the target language. My initial plan would be to focus on English vocabulary and expressions, with learning items organized by topics and difficulty levels.

The database would be designed to manage users, learning items, words or expressions, meanings, example sentences, topics, difficulty levels, practice sessions, exercises, answers, and learning states. The schema would be normalized to at least third normal form and important business rules would be enforced using database constraints and database-side logic.

The main feature would be a stored procedure or function responsible for calculating the priority of learning items. The priority would take into account the number of correct and incorrect answers, the number of previous attempts, the time of the most recent practice, and the difficulty of the item.

I would implement at least two approaches for selecting the next practice sequence. The first could use a simple rule-based strategy, while the second could calculate a weighted priority score. The two strategies would then be compared based on the composition of the selected learning items, their treatment of previous mistakes and repetition frequency, query performance, and behavior with larger amounts of learning-history data.

After the database-side logic is implemented, I would create reproducible test data containing several tens of thousands of practice events and user answers. This data would allow the system to be tested under more realistic conditions and would support the required performance analysis.

I would create complex SQL queries for analyzing user progress, identifying problematic learning items, comparing performance by topic, tracking progress over time, analyzing repetition statistics, and performing multi-table aggregation. For at least five selected queries, I would measure performance before and after applying indexing or query optimization and analyze the resulting execution plans.

The user interface would provide a simple workflow for starting a practice session, receiving the sequence generated by the database logic, submitting answers, and viewing individual learning progress. The interface would not independently implement the learning-item selection algorithm.
