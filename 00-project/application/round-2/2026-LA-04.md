# Smart Parking Garage Management System

## My interpretation of the brief

My understanding of this project is that its main focus is the design and implementation of a reliable relational database system for managing the operation of a parking garage. The web application is primarily intended to demonstrate and interact with the database functionality, while the essential business rules and critical operations must be implemented and enforced at the database level.

The system needs to manage interconnected information about parking garages, floors, parking spaces, customers, vehicles, reservations, parking events, tariffs, payments, subscriptions, maintenance periods, and parking-space states. The database must be designed to at least third normal form and enforce important rules through constraints, stored procedures, functions, transactions, and, where appropriate, triggers.

A particularly important requirement is preventing conflicting reservations when multiple users attempt to reserve the same parking space for overlapping time periods. I understand that this requires careful transaction management and investigation of concurrency-control mechanisms and transaction isolation levels.

The project also requires a significant amount of test data, complex SQL queries, performance measurements, indexing or query optimization, and documentation of the differences between the responsibilities of the web application and the database system.

## Why I am a good fit for this project

I am interested in database-centered application development because it combines software development with practical problems involving consistency, concurrency, and data integrity. A parking garage management system is a realistic example of a transactional system where incorrect handling of simultaneous operations could create serious inconsistencies, such as double booking a parking space.

This project is particularly interesting to me because the main challenge is not simply building a user interface. Instead, it requires designing a system in which the database itself is responsible for enforcing important business rules. I would like to gain more practical experience with stored procedures, transactions, locking, isolation levels, constraints, and query optimization.

I also find the concurrency aspect of the project especially valuable. Comparing different approaches for handling simultaneous reservation requests would provide practical insight into how database systems maintain consistency when several users interact with the same data at the same time.

## Proposed approach

I would begin by analyzing the requirements and designing the relational data model. The schema would include the required entities and relationships while maintaining at least third normal form. Before implementation, I would define the lifecycle of a reservation and parking event, the possible states of a parking space, and the rules governing availability and fee calculation.

The core operations would then be implemented in the database using stored procedures and functions. These operations would include searching for available parking spaces, creating reservations, cancelling reservations where appropriate, handling vehicle entry and exit, updating parking-space states, and calculating parking fees.

For concurrency handling, I would investigate at least two approaches suitable for preventing double booking. For example, I would compare different transaction isolation levels or locking strategies and evaluate their effect on consistency, execution time, and concurrent load. The selected solution would be documented and justified based on the test results.

I would create reproducible test data containing at least one hundred thousand reservation and parking-event records. This data would be used to develop complex SQL queries for occupancy, utilization, revenue, customer and vehicle history, time-interval searches, and multi-table aggregation.

For at least five selected queries, I would record baseline performance, analyze execution plans, apply justified indexes or query improvements, and compare the results quantitatively.

The web interface would remain intentionally limited in scope. It would allow users to search for available parking spaces, create and cancel reservations, and view their own reservations. An operator view would display current occupancy and basic statistics. The interface would use the database-side logic rather than duplicating essential business rules in the application layer.
